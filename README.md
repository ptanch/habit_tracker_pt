# Трекер привычек

Проект **Трекер привычек** — это backend-приложение на Django с API для управления привычками, интеграцией с Telegram и системой отложенных уведомлений через Celery.

---

## ⚙️ Технологии

- Python 3.x
- Django 5+
- Django REST Framework
- Celery
- Redis (для брокера и хранения задач Celery)
- django-cors-headers (CORS)
- PostgreSQL / SQLite (можно выбрать)
- Telegram Bot API
- Переменные окружения для секретных данных и токенов

## 📌 Основной функционал

### Модели

- **User** — кастомный пользователь на основе `AbstractUser`, с полями:
  - email
  - phone
  - avatar
  - telegram
  - `tg_chat_id` для интеграции с Telegram
- **Habit** — привычка пользователя с полями:
  - user
  - place
  - time
  - action
  - is_pleasant
  - related_habit
  - periodicity
  - reward
  - execution_time
  - is_public
  - last_run_at (для отслеживания последнего напоминания)

---

### Эндпоинты API

- **Регистрация пользователя**
- **Авторизация пользователя**
- **Список привычек текущего пользователя** (с пагинацией, 5 привычек на страницу)
- **Список публичных привычек**
- **Создание привычки**
- **Редактирование привычки**
- **Удаление привычки**

Все эндпоинты защищены правами доступа:
- Пользователь может управлять только своими привычками (CRUD)
- Список публичных привычек доступен для чтения всем пользователям

---

### Валидаторы и бизнес-логика

- Нельзя одновременно заполнять `reward` и `related_habit`
- Приятная привычка (`is_pleasant`) не может иметь `reward` или `related_habit`
- Время выполнения привычки не может превышать 120 секунд
- В `related_habit` можно включать только приятные привычки
- Периодичность выполнения:
  - не реже одного раза в 7 дней
  - нельзя не выполнять привычку более 7 дней

---

      "http://localhost:3000",

## ⏰ Celery + Telegram

Проект интегрирован с Telegram для автоматических напоминаний о привычках через **Celery**.

---

### Интеграция с Telegram

- Отправка уведомлений пользователю о привычках через Telegram Bot
- Автоматическая привязка пользователя через поле `tg_chat_id`
- Команда `/start` для приветствия и подтверждения подключения к боту
- Напоминания приходят по времени выполнения привычки, с учётом последнего напоминания (`last_run_at`)

---

### Отложенные задачи (Celery)

- Настроен **Celery** для обработки задач в фоне
- Настроен **Celery Beat** для периодических напоминаний о привычках
- Redis используется как брокер и для хранения результатов задач

---

### Настройка Telegram

1. Создать бота через BotFather и получить токен.
2. Добавить поле `tg_chat_id` в модель пользователя (`User`).
3. В админке или через shell указать `tg_chat_id` для пользователя.
4. При старте бота (`/start`) можно автоматически сохранять `chat_id`.

---

### Настройка Celery

1. В `settings.py` настроить брокер и результат:

```python
CELERY_BROKER_URL = 'redis://localhost:6379/1'
CELERY_RESULT_BACKEND = 'redis://localhost:6379/1'
CELERY_BEAT_SCHEDULER = 'django_celery_beat.schedulers:DatabaseScheduler'
```

## Как запустить проект

1. Создать и активировать виртуальное окружение
2. Установить зависимости:
```bash
pip install -r requirements.txt
```

3. Применить миграции:
```bash
python manage.py migrate
```

4. Создать суперпользователя:
```bash
python manage.py createsuperuser
```

5. Запустить Redis (локально или через Docker)
6. Запустить Celery worker и beat:
```bash
celery -A config worker -l info
celery -A config beat -l info
```

7. Запустить сервер Django:
```bash
python manage.py runserver
```

8. Проверять работу API через Postman или фронтенд

## 🚀 Контейнеризация и CI/CD

В проекте реализована полноценная контейнеризация и автоматизированный процесс CI/CD с использованием Docker, Docker Compose и GitHub Actions.

---

### 🐳 Контейнеризация проекта

Все сервисы проекта вынесены в отдельные контейнеры:

- Django - основной backend приложения
- PostgreSQL - база данных
- Redis - брокер сообщений
- Celery - асинхронные фоновые задачи
- Celery Beat - планировщик периодических задач
- Nginx - reverse proxy и HTTP-сервер

Для каждого сервиса используется отдельный контейнер, что обеспечивает:
- изоляцию сервисов,
- воспроизводимость окружения,
- простоту деплоя и масштабирования.

**Используемые файлы**

`Dockerfile` — сборка образа Django-приложения (используется для `web`, `celery`, `celery-beat`)
`docker-compose.yml` — оркестрация всех сервисов проекта
`.env` — переменные окружения (не хранится в репозитории)

---

### ▶️ Запуск проекта локально

1️⃣ Клонирование репозитория
```bash
git clone https://github.com/ptanch/habit_tracker_pt.git
cd habit_tracker_pt
```
2️⃣ Создание .env файла

Создайте файл `.env` в корне проекта и заполните его по примеру:
```
SECRET_KEY="django-secret-key"
DEBUG=1

POSTGRES_DB=habit_tracker
POSTGRES_USER=habit_tracker
POSTGRES_PASSWORD=habit_tracker
DB_HOST=db
DB_PORT=5432

REDIS_HOST=redis
REDIS_PORT=6379
```

3️⃣ Запуск проекта одной командой
```bash
docker compose up -d --build
```

После успешного запуска:
- приложение доступно по адресу: http://localhost
- все сервисы поднимаются автоматически
- применяются healthcheck-и для `PostgreSQL`, `Redis` и `Django`

Проверка состояния контейнеров:
```bash
docker compose ps
```

### 🔁 CI — Continuous Integration

В проекте настроен CI с помощью **GitHub Actions**.

**CI workflow выполняет**:
- установку зависимостей через Poetry,
- запуск линтинга (`flake8`),
- запуск тестов Django,
- проверку возможности сборки Docker-образов.

CI запускается при:
- `push` в ветки `develop` и `feature/**`,
- создании Pull Request в ветку `develop`.

Файл CI workflow:
```
.github/workflows/ci.yml
```

---

### 🚀 CD — Continuous Deployment

После успешного прохождения CI настроен автоматический деплой проекта на удалённый сервер.

**Что делает CD**:
- подключается к серверу по SSH,
- обновляет код проекта,
- пересобирает Docker-образы,
- обновляет и перезапускает контейнеры через `docker compose`.

Деплой полностью автоматизирован и не требует ручного вмешательства.

Файл CD workflow:
```
.github/workflows/deploy.yml
```

---

### 🖥 Настройка удалённого сервера

Удалённый сервер подготовлен для работы с Docker:
- установлен **Docker**
- установлен **Docker Compose**
- настроен SSH-доступ
- добавлен SSH-ключ GitHub Actions в `~/.ssh/authorized_keys`
- отключён системный nginx (используется nginx в Docker)

Проект разворачивается в директории:
```
/opt/habit_tracker
```

Все переменные окружения для сервера передаются через **GitHub Environment Secrets**.

---

### 🔐 Secrets и безопасность

- Все чувствительные данные (`SECRET_KEY`, данные БД, SSH-ключи)
**не хранятся в репозитории**
- Используются: 
    - **GitHub Environment Secrets** — для CI/CD
    - `.env файл` — для локального запуска
